# Product Context

## Why this exists

Engineers need repeatable automation for complex, multi-step workflows (e.g., tmux orchestration, device access, log capture, and reporting). The step engine provides a clear, visualizable, and extensible mechanism for this automation.

## Users

- Automation engineers
- Test engineers (e.g., thermal testing)
- Developers maintaining step libraries

## UX goals

- Clear, graph-based workflows
- Safe shared-state handling
- Fast iteration on step nodes
